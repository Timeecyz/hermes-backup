# 蛮子销售深度学习系统

## 核心方法论

### 费曼大法 L1-L5 分级

用「说人话」检验是否真正掌握：

| 等级 | 受众 | 要求 |
|------|------|------|
| L1 | 小孩/纯外行 | 一个生活类比，一句话说清楚 |
| L2 | 普通人 | 能举生活化例子，对方能听懂 |
| L3 | 有基础的人 | 能联系客户场景，带具体案例 |
| L4/L5 | 同行/专家 | 能回答追问，能辩倒我 |

**「听过不等于知道，知道不等于理解，只有深度理解的东西才能费曼出来。」**

---

## 三种触发模式

### 模式一：读后费曼（最常用）

**触发词：**「我学完了」「读后费曼」「看完这篇」
**蛮子做什么：** 用 **2W2H模型** 讲给我听

> **W1：** 这个概念/产品是什么？（一句话说清楚）
> **W2：** 为什么重要？解决了什么问题？
> **H1：** 它是怎么运作的？
> **H2：** 我怎么用它？（卖保险/跟客户讲/处理异议）

**我做什么：** 听后打分 + 追问

- ✅ **L3+**：指出哪里讲得好，继续深挖
- ⚠️ **L2**：指出没有意识到的问题，继续追问
- ❌ **L1或以下**：推荐补充什么，哪里理解有偏差

---

### 模式二：随机抽考（每周一题）

**触发词：**「你出题」「考考我」「每周一题」
**我做什么：** 从蛮子知识薄弱区出一题

```
📋 本周考点：{topic}

请在3分钟内，用自己的话解释：
{question}

并给出一个客户会问的具体问题，以及你的回答。
```

**蛮子回答后：**
- ✅ **懂了** — 指出哪里讲得好
- ⚠️ **表面懂了** — 指出没有意识到的问题
- ❌ **不知道** — 推荐看什么/补什么

---

### 模式三：案例复盘（每次销售后）

**触发词：**「案例复盘」「这次客户」「你帮我分析」
**蛮子做什么：** 讲清楚

1. 客户是什么情况？（背景、需求、顾虑）
2. 你说了什么、为什么这样说？
3. 客户反应如何？
4. 你事后觉得哪里可以更好？

**我做什么：** 评估讲解是否抓住本质，给出调整建议

## 蛮子知识薄弱区清单

（我会按优先级出题，每次考完标记，下次轮换）

- [ ] 港险与内地险的核心差异（储蓄/保障/法律）
- [ ] 每一款主打产品的IRR和保证vs非保证结构
- [ ] 跨境投保的合规边界（保监局最新发声要点）
- [ ] 不同人生阶段的保险配置逻辑
- [ ] 高净值客户的财富传承需求
- [ ] 常见异议处理：「汇率风险」「理赔难」「缴费周期」
- [ ] 保险法关于跨境保单的关键条款
- [ ] 客户分类（首次接触/比较期/决策期）的话术差异

---

## 操作原则

1. **生成优先于复述** — 让蛮子自己讲，不让她抄笔记
2. **追问到不能再追问为止** — 真正的理解经得起追问
3. **联系客户场景** — 能讲给客户听才是真的懂
4. **每周一题自动运行** — 防止知识积压不复习
5. **案例复盘不过夜** — 趁热回顾，印象最深

## 客户档案管理（吸收自 client-file-management）

> 成交即建档，档案不完整不准关闭成交流程。

### 标准文件夹结构（6类）

```
📁 INI-YYYY-NNN_姓名缩写_地区/
├── 📁 01_身份证明/
├── 📁 02_银行卡/
├── 📁 03_保单资料/
├── 📁 04_合同协议/
├── 📁 05_财务资料/
└── 📁 06_沟通记录/
```

### 文件命名规则

| 类型 | 格式 | 举例 |
|------|------|------|
| 客户根文件夹 | `INI-YYYY-NNN_姓名缩写_地区` | `INI-2026-001_YZL_XA` |
| 身份证 | `ID_日期_备注` | `ID_20260528_身份证正面.jpg` |
| 银行卡 | `BC_日期_银行` | `BC_20260528_工行.jpg` |
| 保单 | `PO_日期_产品名` | `PO_20260228_平安福.pdf` |
| 合同 | `CT_日期_合同类型` | `CT_20260301_投保单.jpg` |
| 发票 | `IV_日期_金额` | `IV_20260301_5000元.jpg` |
| 沟通记录 | `MSG_日期_渠道` | `MSG_20260520_微信.jpg` |

**文件类型代码速查：** ID=身份证, BC=银行卡, PO=保单, CT=合同, IV=发票, MSG=沟通记录

### Excel 资料清单结构

- **Sheet 1**：客户资料清单（编号/姓名/地区/身份证/银行卡/保单/合同/发票/沟通记录/建档日期/备注）
- **Sheet 2**：资料类型代码说明

**状态标注：** ✅=已收全, ⚠️=部分缺失, ❌=完全缺失

### 飞书多维表格联动（典型坑）

- **症状**：`404 page not found` 或 `code 99991672`
- **原因**：App 属于 A 飞书组织，多维表格属于 B 组织（跨组织权限问题）
- **解法**：把多维表格移至 App 所在空间，或在多维表格「分享」中搜索 App ID 授予权限

**注意**：飞书 bitable（多维表格）≠ 飞书电子表格（sheets）。前者 API path 为 `bitable/v1/bitables/{token}`，后者为 `sheets/v3/spreadsheets/{token}`
