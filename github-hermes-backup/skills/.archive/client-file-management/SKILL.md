# Client File Management（客户档案资料管理）

## 适用场景
- 新建成交客户档案时
- 整理现有客户资料混乱时
- 需要检查客户资料完整性时
- 设计客户资料交接清单时

## 核心概念

**目标：** 让每个客户的所有资料（身份证/银行卡/保单/合同/发票/沟通记录）都有固定位置，查找5秒内，交付时一键打包。

**两个交付物：**
1. **文件夹模板**（纸质/电子档案的物理结构）
2. **资料清单 Excel**（完整性追踪系统）

---

## 标准文件夹结构（6类）

```
📁 INI-YYYY-NNN_姓名缩写_地区/
├── 📁 01_身份证明/
├── 📁 02_银行卡/
├── 📁 03_保单资料/
├── 📁 04_合同协议/
├── 📁 05_财务资料/
└── 📁 06_沟通记录/
```

## 文件命名规则

| 类型 | 格式 | 举例 |
|------|------|------|
| 客户根文件夹 | `INI-YYYY-NNN_姓名缩写_地区` | `INI-2026-001_YZL_XA` |
| 身份证 | `ID_日期_备注` | `ID_20260528_身份证正面.jpg` |
| 银行卡 | `BC_日期_银行` | `BC_20260528_工行.jpg` |
| 保单 | `PO_日期_产品名` | `PO_20260228_平安福.pdf` |
| 合同 | `CT_日期_合同类型` | `CT_20260301_投保单.jpg` |
| 发票 | `IV_日期_金额` | `IV_20260301_5000元.jpg` |
| 沟通记录 | `MSG_日期_渠道` | `MSG_20260520_微信.jpg` |

**文件类型代码速查：**
- ID = 身份证
- BC = 银行卡
- PO = 保单
- CT = 合同
- IV = 发票
- MSG = 沟通记录

## 使用流程

### 新建客户档案
1. 复制 `client_files_template/` 文件夹模板
2. 重命名为 `INI-YYYY-NNN_姓名缩写_地区`
3. 向客户收集资料，按类存入对应子文件夹
4. 在 Excel 清单中新增一行，标注收到状态
5. 缺失的资料在备注栏写明"还缺XX"

### 定期检查
每月一次，检查 Excel 中 ⚠️ 和 ❌ 的客户，补齐缺失资料。

### 交接/备份
客户档案打包成 zip，一键发给客户确认留存。

## 常见问题

**Q: 客户不愿意提供银行卡/身份证复印件怎么办？**
→ 提供电子版照片（微信发送截图），存入对应文件夹，标注"电子版-客户自拍"

**Q: 有些沟通记录没有留存怎么办？**
→ 在 MSG 文件夹中放一个 `MSG_NA_20260528_无记录.md` 占位文件，避免以后混淆是"没留"还是"没发生"

**Q: 客户资料散落在多个微信对话框里？**
→ 先在 Excel 中标注来源渠道（"微信对话-2025.3.12"），再逐个保存进文件夹

## 飞书多维表格联动

### 典型坑：跨组织权限（99991672 / 404）
- **症状**：飞书 API 访问多维表格返回 `404 page not found` 或 `code 99991672`
- **原因**：App（如 `cli_aa9abc638cf91bb4`）属于 A 飞书组织，多维表格属于 B 组织（刘裕家族办公室 vs 启富未来）
- **解法（二选一）**：
  1. 把多维表格移至 App 所在空间：飞书内「···」→「移至其他空间」→ 选择启富未来
  2. 在多维表格「分享」中搜索 App ID，授予读/写权限

### 写入飞书 bitable 的标准字段映射（启富未来客户总表）
| Excel 列名 | 飞书字段 | 说明 |
|-----------|---------|------|
| 分级 | 分级 | A/B/C/D |
| 可投资产体量 | 可投资产体量 | S/A/B/C/D |
| 编号 | 编号 | INI-YYYY-NNN |
| 姓名 | 姓名 | |
| 电话 | 电话 | |
| 来源 | 来源 | 亲戚/朋友/转介绍... |
| 关联介绍人 | 关联介绍人 | |
| 成交时间 | 成交时间 | YYYY-MM-DD |
| 上次联系时间 | 上次联系时间 | YYYY-MM-DD |
| 重要时间节点 | 重要时间节点 | |
| 基金/内地保险/境外保险/信托... | 对应勾选字段 | 已成交/待成交 |

> **注意**：飞书 bitable（多维表格）≠ 飞书电子表格（sheets）。前者 API path 为 `bitable/v1/bitables/{token}`，后者为 `sheets/v3/spreadsheets/{token}`，权限体系独立。
