# 工作流磨合参考

> 本次会话（2026-05-26）从两篇 Hermes 文章提炼的磨合原则。

## 7条合作原则（已生效）

| # | 原则 | 落地方式 |
|---|------|---------|
| 1 | **给信息先说「有什么用」** | 任何外部输入，结论先行，格式：「【这条对你有什么用】→ 关键信息 → 建议」 |
| 2 | **目标你定，过程我补** | 你只说「要什么」，我拆解步骤、查资料、执行，不用你指挥 |
| 3 | **重复工作流 → 我主动沉淀** | 发现规律后主动提「要不要做成 Cron/Skill」，你点头我执行 |
| 4 | **我主动提建议** | 看到值得做的点直接说，不等你问 |
| 5 | **流程迭代，不设计后执行** | 边干边沉淀，不等完美方案再动手 |
| 6 | **你决策，我执行+记录** | 你做判断性决定，我负责执行和信息整理 |
| 7 | **分层记忆，共同沉淀** | 我的 MEMORY.md + Notion = 共同记忆，我主动存，你随时纠错 |

## 升级安全方案

**现状：** Hermes 数据都在 `~/.hermes/` 外围，升级只动主程序。

**风险：** 备份脚本（`hermes_backup.sh`）漏了 config.yaml、SOUL.md、AGENTS.md、USER.md、IDENTITY.md。

**行动：** 系统快照表已写入 MEMORY.md。升级前确认备份完整。
